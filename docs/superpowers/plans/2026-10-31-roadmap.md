# Canonball Build Roadmap

Spec: `docs/superpowers/specs/2026-10-31-canonball-app-design.md`

The app is built in phases. Each phase ends with a working app you can use, and each gets its own plan in `docs/superpowers/plans/`. Only Phase 1's plan is written up front. Every later plan is written **at the start of its phase, in a fresh session**, so it can use the real names and interfaces the earlier phases produced instead of guesses.

## Starting a phase in a fresh session

1. Read the spec, this roadmap, and `OPEN_WORK.md`.
2. Read the previous phase's plan. Its **Interfaces** blocks list the functions and types now available.
3. If the phase has no plan yet, use superpowers:writing-plans with the phase description below and save it as `docs/superpowers/plans/YYYY-MM-DD-phase-N-<name>.md`.
4. Execute the plan. At the end, move the phase from `OPEN_WORK.md` to `COMPLETED_WORK.md`.

## Phases

| # | Phase | Usable result | Plan |
|---|---|---|---|
| 1 | **Editor shell** | Open or create a project, browse the tree, write in a WYSIWYG editor that saves markdown, light/dark/system theme | `2026-10-31-phase-1-editor-shell.md` |
| 2 | **Writing aids** | Chromium spellcheck with right-click suggestions; Harper grammar underlines with suggestions; flag-only, never auto-fix | to write |
| 3 | **AI permissions** | ✎/👁/⊘ badges in the tree, folder defaults and file overrides, prose folders, the first-open "which folders hold prose?" prompt, `.canonball/project.json`, and the main-process access layer that refuses every AI write to a prose folder | to write |
| 4 | **AI connection & chat** | Settings for Anthropic / OpenAI / Google keys (Keychain via `safeStorage`) and local OpenAI-compatible URLs; model picker; streaming chat panel; chats saved in `.canonball/chats/` with a `.gitignore` entry | to write |
| 5 | **AI file tools & proposals** | AI tools (list, read, propose edit, create note) gated by Phase 3's access layer; Accept/Reject cards for edits and new files; fallback for models without tool calling; `style_rules.md`, `names_to_avoid.md` and `memory/` in the AI's instructions; the "never prose into drafts" rule tested end to end | to write |
| 6 | **Brainstorm sessions** | Start a session with a goal, the v1 brainstorm stance, end-of-session log in `sessions/` from the template, per-decision canon promotion cards, next session reads the last "Next Session" | to write |
| 7 | **Package & release** | Signed Mac build, app icon, README for writers, open-source license | to write |

Deferred until after the author has used the app: **export** (Word, EPUB, PDF). See `OPEN_WORK.md`. Windows and Linux builds come after Phase 7.

## Why this order

Phases 1–2 make a writing app that's useful with no AI at all. Phase 3 lands before any AI code so that the safety rule (the AI never edits prose) is in place before a model can call a tool. Phase 4 proves the connections before Phase 5 gives the AI tools that change files.
